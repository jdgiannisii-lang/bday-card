# Phase 1 — UI Design Contract

> Visual and interaction contract for the Stage 0 self-serve card maker. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **North star:** the maker is an *extension of the existing card's handcrafted visual language* (`index.html`), not a generic form. Every new surface reuses the card's tokens, fonts, paper texture, and soft shadows. It must feel like the same hand made it. The recipient open stays sacred: vanilla HTML/CSS, no SPA framework, no blocking work before the craft paints.
>
> **Hard rule inherited project-wide:** ZERO em-dashes (U+2014) in ANY copy or comment, including all copy in this spec and everything the maker emits. Enforced by `grep -c "$(printf '\xe2\x80\x94')"`. Use periods, commas, parentheses, or hyphens.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla HTML/CSS/JS, single-file pattern preserved; no React/Next/Vite, so shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none (hand-built; reuse `index.html` patterns) |
| Icon library | none (inline SVG paths, matching the existing card's chevron/heart SVGs); QR via a tiny client lib or pre-rendered image |
| Font | Caveat (handwritten), Cormorant Garamond (display/foil serif), Outfit (UI sans) — the existing three families, loaded the same way for Stage 0 (self-hosting deferred to Phase 2) |

All tokens below are inherited verbatim from the `:root` block in `index.html`. The maker MUST reuse these CSS custom properties, not introduce new hex values.

---

## Spacing Scale

Declared values (all multiples of 4; matches the card's existing rhythm of 8/16/24/28/30):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, icon-to-label spacing, field hint offset |
| sm | 8px | Compact spacing, chip internal padding, scroll-fade math |
| md | 16px | Default gap between form fields and inside-scroll content |
| lg | 24px | Group spacing (field group to field group), card inner padding |
| xl | 32px | Section breaks (form block to share block), landing vertical rhythm |
| 2xl | 48px | Major surface breaks, top/bottom breathing room on the maker |
| 3xl | 64px | Page-level spacing on wider viewports only |

Exceptions:
- **44px minimum touch target** for all tap controls (occasion/effect pickers, photo-upload affordance, copy-link button, primary CTA). Mobile-first; most cards open on phones.
- **--radius: 14px** is the single corner system everywhere (inherited). Chips/pills may use a fully-rounded pill radius (`999px`) since they are small controls, but cards, fields, and the upload zone use 14px.

---

## Typography

Three families, but a tight role set. Sizes use the card's existing `clamp()` approach so the maker scales fluidly on mobile. Weights are capped: Outfit at 400/500, Caveat at 500/600, Cormorant at 600 only.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Body / field input | Outfit | 16px (never below 16px on inputs, to prevent iOS zoom-on-focus) | 400 | 1.5 |
| Label / eyebrow | Outfit | 10px uppercase, .34em letter-spacing (matches `.eyebrow` / `.open-label`) | 500 | 1.2 |
| Field hint / helper | Caveat | 15px | 500 | 1.32 |
| Heading (form/landing) | Cormorant Garamond | clamp(26px, 7vw, 34px) (matches `.greeting`) | 600 | 1.06 |
| Display (landing hero) | Cormorant Garamond, italic | clamp(40px, 13vw, 60px) (matches `.cover-title`, gold foil) | 600 | 1.06 |
| The recipient CTA | Caveat | 20px (matches `.replay`) | 600 | 1.32 |

Notes:
- The handwritten voice (Caveat) is reserved for human-warmth copy: the CTA, field hints, the "I'll send you a link" reassurance, the polaroid-style caption on the live preview. Never use Caveat for system/error chrome.
- Outfit carries all functional UI text (labels, inputs, buttons-as-chrome, validation).

## Color

All values inherited from `index.html` `:root`. No new colors introduced. The 60/30/10 split below maps the existing warm palette onto the maker surfaces.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--paper` #f8f1e3 (on `--paper`/`#f3e3d3` radial gradient body) | Page background, the maker canvas, field fills |
| Secondary (30%) | `--paper-warm` #f3e8d4 / `--paper-edge` #e7d8bf | Field borders, the upload dropzone surface, chip backgrounds, card-like panels, the share-state card |
| Accent (10%) | `--rose` #c25470 / `--rose-deep` #9e3a55 | See reserved-for list below |
| Destructive | `--rose-deep` #9e3a55 (reused; no new red introduced) | Remove-photo control, validation error text. Kept warm, never a hard system red. |

Text colors (inherited): `--ink` #46362d (primary copy), `--ink-soft` #7a685b (hints, labels, placeholders). No pure black. Gold foil tones (`--gold-lo/mid/hi`) reserved for the display title only, exactly as the card uses them.

**Accent (rose) reserved for, and ONLY for:**
1. The primary "create / get my link" button fill and the recipient "Make one for someone you love" CTA underline.
2. The selected state of an occasion/effect chip (rose border + rose-deep label).
3. Focus ring on form fields (a soft `--rose` outline, not browser-blue).
4. The wax-seal heart / single decorative accent on the landing.
5. Validation error text (uses `--rose-deep`).

Never apply rose to: every interactive element, body text, borders at rest, or large fills. Rose stays the single rich accent (HSL saturation under 60%, per the card's own rule).

## Copywriting Contract

All copy in the card's voice: warm, handmade, plain. No growth-hack/marketing tone. ZERO em-dashes.

| Element | Copy |
|---------|------|
| Recipient CTA (on the card, after animation settles) | `Make one for someone you love →` with a smaller Caveat second line `It's free, and it takes a minute.` (rose, single underline, NOT a button) |
| Maker landing hero | Eyebrow `FOR SOMEONE YOU LOVE` over display title `Make a card` |
| Maker landing subhead | `A little hand-animated card they open right in their browser. No app, no signup.` |
| Primary CTA (create form submit) | `Get my link` (verb + noun; not "Submit" or "Create card") |
| Photo-upload affordance | `Add a photo` with hint `One photo, portrait looks best.` |
| Recipient-name field label | `Their first name` |
| Message field label | `Your note` with Caveat hint `Write it like you'd say it.` |
| Signoff field label | `How you sign it` (e.g. `With love, JD`) |
| Occasion picker label | `What's the occasion?` (chips: `Just because` / `Thinking of you` / `Birthday`) |
| Effect picker label | `Pick the magic` (chips for the existing hand-coded effects: e.g. `Hearts` / `Confetti` / `Petals`) |
| Empty state heading (create form, untouched) | (form is the entry surface; no data-empty state. Live preview before input shows) `Your card will appear here.` |
| Empty state body | `Fill it in and watch it come together.` |
| Share-state success heading | `Your card is ready.` |
| Share-state body | `Send this link to their phone. They just tap it.` |
| Copy-link button | `Copy link` → on success, transient `Copied` (Caveat, rose) |
| QR caption | `Or let them scan this.` |
| Error state (upload too large) | `That photo's a little big. Try one under 10MB.` |
| Error state (upload failed / network) | `That didn't go through. Check your connection and try again.` |
| Error state (missing required field) | Inline under field, `--rose-deep`: e.g. `Add their first name` / `Write a note first` |
| Error state (save/link generation failed) | `We couldn't make your link just now. Give it another try.` with a retry affordance |
| Destructive confirmation (remove uploaded photo) | Remove photo: inline `✕` on the photo thumb, immediate (low-stakes, re-uploadable), no modal. Caption confirms: `Photo removed.` |

There are no high-stakes destructive actions in this phase (no delete-account, no irreversible publish). Photo removal is the only "destructive" affordance and is intentionally frictionless + reversible.

## Surface Contracts

This phase introduces three new surfaces. Each is specified below so the executor can build without design ambiguity. Mobile-first; all layouts are single-column on phones.

### Surface A — Maker Create Form

**Purpose:** how a sender personalizes a card. Fields (locked by CONTEXT D-04): recipient first name, 1 photo, message, signoff, occasion preset, effect choice.

- **Layout:** single column, centered, max content width `min(92vw, 420px)` (echoes the card's `min(84vw, 350px)` but a touch wider for inputs). Vertical rhythm uses `lg` (24px) between field groups, `xl` (32px) before the submit. Page background is the inherited radial paper gradient.
- **Field styling:** fields sit on `--paper` with a 1px `--paper-edge` border, `--radius` (14px) corners, 16px Outfit input text, `--ink-soft` placeholders. Focus = soft `--rose` outline (no blue). Labels above each field in the Outfit eyebrow style (10px uppercase) OR sentence-case 14px Outfit (executor's choice, consistent across all fields). Hints in Caveat 15px `--ink-soft`.
- **Photo-upload affordance:** a tappable dropzone, `--paper-warm` fill, dashed `--paper-edge` border, 14px radius, min height ~140px, label `Add a photo` + camera/plus inline SVG in `--ink-soft`. On select: client-side downscale/crop toward ~3:4 (matches the polaroid `146×172` ratio), show a taped-polaroid-style thumbnail preview (reuse `.polaroid` styling: white frame, slight `rotate(-3deg)`, soft shadow) with an `✕` remove control. This makes the upload feel like placing a photo into the card, not attaching a file.
- **Occasion picker:** 3 pill chips (`Just because` / `Thinking of you` / `Birthday`), single-select, default `Just because`. Rest state: `--paper-warm` fill, `--ink-soft` Outfit label, no border. Selected: `--rose` 1.5px border + `--rose-deep` label. 44px min height. Selecting `Birthday` reveals the milestone medallion in the preview; other occasions hide it (per D-04, same template, cover title swaps).
- **Effect picker:** same chip pattern as occasion, single-select, mapping to the existing hand-coded canvas effects only (hearts / confetti / petals + any 1-2 existing variants). No video/overlay options (deferred). Optionally show a tiny static glyph per effect.
- **Live preview (recommended, not required for the gate):** if feasible within the single-file lightness budget, render a scaled-down live card preview that updates as fields change (name → greeting, photo → polaroid, message → note, occasion → cover title + medallion). If a full live preview is too heavy, fall back to the empty-state copy (`Your card will appear here.`) and a static cover mock that updates name + occasion title only. The preview reuses the real card components, never a separate look.
- **Primary action:** full-width `Get my link` button, `--rose` fill, paper-colored label, 14px radius, 44px+ height, Outfit 500. On submit: disabled + Caveat micro-copy `Making your link…`. The card persists (Supabase free, D-01) and the form transitions to Surface B.
- **Hidden tracking fields:** carry `?ref=<card_id>` (the spawning card) and the optional "who sent you the card you saw?" field, plus the consent checkbox (`I have permission to use this photo, and I understand this is an early experiment.`) per the Stage 0 spec §5.2. Consent checkbox is required to enable submit.

### Surface B — Share State (post-create)

**Purpose:** the result after `Get my link` — the shareable `/c/<token>/` link + QR.

- **Layout:** replaces the form in place (no full reload). A single `--paper-warm` panel (card-like, 14px radius, soft shadow matching `.polaroid`'s `0 10px 20px rgba(70,54,45,.22)`).
- **Content order:** heading `Your card is ready.` (Cormorant 600) → body `Send this link to their phone. They just tap it.` → the link shown in a read-only field with a `Copy link` button (rose) → a centered QR with caption `Or let them scan this.` → a quiet secondary text link `Make another` that resets to a blank form.
- **Copy feedback:** on copy, button label swaps to `Copied` in rose for ~1.5s, then reverts. No toast library.
- **Optional preview-open:** a small `Preview it` text link opening the live `/c/<token>/` in a new tab so the sender sees what the recipient gets.

### Surface C — Recipient CTA (on the card view) + Maker Entry

**Purpose:** after the animation settles, reveal the "Make one for someone you love →" CTA in the card's own voice, dropping the recipient into the maker carrying `?ref=<card_id>`.

- **Placement & reveal:** reuse the existing replay-reveal timer (`~line 888`, the `setTimeout(... 1500ms)` that already shows `.replay`). The CTA appears in the same understated bottom region, alongside or just above `read it again`. It fades in (opacity + slight translateY), never slides aggressively. Respect `prefers-reduced-motion`: under reduced motion the CTA is present immediately with no transition (and that session is tagged + EXCLUDED from the engagement denominator per D-02, but the CTA still shows).
- **Styling (locked by CONTEXT specifics):** Caveat font, `--rose-deep` color, a single 1.5px underline (`border-bottom`, like `.replay`), NOT a filled growth button. Hover/focus: shift toward `--rose`. 44px tap target. Text: `Make one for someone you love →` with optional smaller Caveat line `It's free, and it takes a minute.`
- **Analytics hook:** tapping fires `cta_clicked` (PostHog, cookieless config from the Stage 0 spec §1a) and navigates to the maker with `?ref=<card_id>&g=<generation>` appended for generation attribution.
- **Maker landing (the entry the CTA lands on, also the entry when someone opens the maker link directly):** the inherited radial paper background, eyebrow `FOR SOMEONE YOU LOVE`, gold-foil display title `Make a card` (reuse `.cover-title` styling), subhead in Outfit, and a single primary affordance scrolling/leading into Surface A. One decorative wax-seal heart accent (reuse `.seal` styling, optional). Keep it light: this is the front door, not a marketing page.

## Interaction & Motion Contract

- **Recipient open is sacred:** no SPA framework on the `/c/<token>/` view; it stays the vanilla single-file engine plus the inlined card data, analytics snippet, and CTA. No blocking network call before the craft paints (D-01: read path stays simple; prefer inlining the card JSON server-side per Claude's-discretion note).
- **prefers-reduced-motion:** honored everywhere. The maker form has no decorative motion to suppress; transitions (chip select, preview update, copy feedback, share-state swap) are instant or near-instant under reduced motion. On the card, the existing `@media (prefers-reduced-motion: reduce)` block already removes celebration motion; the CTA must appear in that state too (it just appears without the fade).
- **Touch:** 44px minimum targets, no hover-only affordances, `-webkit-tap-highlight-color: transparent` inherited.
- **Validation:** inline, on submit-attempt (not aggressive on-blur), error copy in `--rose-deep` Caveat-free Outfit under the offending field. Consent checkbox required.
- **No new heavy dependencies:** QR generation should be a tiny client-side lib or a pre-rendered image; analytics is the PostHog snippet only. Preserve the single-file lightness ethos on the recipient view.
