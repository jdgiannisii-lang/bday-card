## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recipient browser to PostHog | Event payloads (card_id, generation, dwell) leave the browser for PostHog Cloud |
| card view to maker (CTA hop) | The card_id and generation cross via URL params into the next card's attribution |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | PostHog event payloads | low | mitigate | Cookieless (no cookies/storage); no PII beyond a first name already in the card; no session recording (research Pattern 3) |
| T-02-02 | Tampering | client-supplied ?g generation value | low | accept | A recipient could spoof a generation number; for the controlled cohort the Google Sheet ledger (verified propagation) is the source of truth, not the client value (D-03, specifics) |
| T-02-03 | Repudiation | engaged double-count or wrong-session count | medium | mitigate | Module-level dedupe (fires once) + reduced-motion exclusion so the denominator stays honest (research Pitfall 5, D-02) |
| T-02-04 | Denial of Service | analytics blocking the sacred open | high | mitigate | Every PostHog call guarded by `if (window.posthog)`, fire-and-forget, never awaited before paint (research anti-pattern) |
| T-02-SC | Tampering | esm.sh import of posthog-js | medium | mitigate | Major-pin `@1`; posthog-js Approved in the research audit (false too-new SUS); prefer the inline snippet for lightness |
