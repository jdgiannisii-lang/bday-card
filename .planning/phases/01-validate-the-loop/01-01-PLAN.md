## Phase Goal

**As a** sender in the controlled Stage 0 cohort, **I want to** fill a small form and get a link I can text to someone, **so that** they open a beautiful hand-animated card in their browser with zero friction (and the loop can be measured).

<objective>
Stand up the Walking Skeleton: the thinnest real end-to-end loop. A sender fills the maker form, a card row plus photo persist in Supabase free tier under an unguessable nanoid token (per D-01), and a recipient opening `/c/<token>/` watches the existing `index.html` canvas engine play with the sender's content. This plan proves the whole stack (write, route, read, render) before any instrumentation or polish is layered on.

This is the architectural backbone for Plans 02 and 03; see SKELETON.md for the locked decisions.

Purpose: De-risk every hard part of Stage 0 in one slice (Supabase write/read, the GitHub Pages `/c/<token>/` routing gotcha, the engine bridge, the sacred non-blocking open). Analytics, validation, share polish, and the decision ledger sit on top of this working loop.
Output: `supabase/migrations/0001_cards.sql`, `shared/supabase.js`, `shared/engine-bridge.js`, `maker.html`, `card.html`, `404.html`, and a live Supabase project.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sender browser to Supabase (anon insert) | Untrusted form input (name, message, signoff, photo) crosses into the cards table and Storage |
| recipient browser rendering stored content | Stored card content is read back and injected into the recipient DOM |
| public internet to /c/<token>/ | Anyone with the token (or guessing) can read a card; the token is the only gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | card content rendered in card.html/404.html | high | mitigate | Render all user text via `textContent`/`createElement`, never `innerHTML`; engine slots set text, not parsed HTML (research V5) |
| T-01-02 | Information Disclosure | cards table public SELECT USING(true) | medium | accept | Token-as-capability for a controlled cohort; no listing UI; SECURITY DEFINER RPC noted as the Phase 4 hardening (D-01, research Pattern 1) |
| T-01-03 | Information Disclosure | photo in public Storage bucket | low | mitigate | Unguessable nanoid path (photos/<token>.jpg); directory listing OFF; signed URLs deferred to Phase 4 |
| T-01-04 | Information Disclosure | anon key + Supabase URL in client | low | accept | Both public by design; RLS is the real control; service_role key never in client code |
| T-01-05 | Denial of Service | anon INSERT as an open write endpoint | low | accept | Controlled cohort, low volume; Turnstile/rate-limiting is the Phase 4 control, not built now |
| T-01-06 | Spoofing | malicious/illegal photo upload | medium | accept | Out of scope by decision for the controlled cohort; founder keeps a manual delete-the-row unpublish path; full moderation/CSAM is the Phase 4 go-public gate |
| T-01-SC | Tampering | esm.sh CDN imports (supabase-js, nanoid) | high | mitigate | Major-pin in the import URL; all packages Approved in the research Package Legitimacy Audit (SUS verdicts are false too-new positives); no human-verify checkpoint required |
</threat_model>
